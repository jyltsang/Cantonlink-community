# The AI tutor

The learning site can connect to an AI model **with your own API key**: Claude, OpenAI, Google Gemini, or a free model running on your own computer. Connecting one unlocks:

- **AI tutor:** a chat screen where you practise conversations in Cantonese, as a Friend (casual) or a Sifu (who corrects every mistake), at your level and in a scenario you choose.
- **Check my sentence:** write something in Cantonese and the tutor corrects it, naming the grammar pattern.
- **Explain with AI**, on every grammar page: a fresh explanation with new examples.
- **Translate with AI**, in Look up: when a phrase isn't in the library.

Everything else on the site works without a key.

**Every AI reply is checked against this library before you rely on it.** See [how replies are checked](#how-replies-are-checked).

## 1. Get a key

| Provider | Where | Notes |
|---|---|---|
| **Claude (Anthropic)** | [console.anthropic.com](https://console.anthropic.com/settings/keys) | Default model `claude-opus-5-5`. Strong at Cantonese and at following the reply format. |
| **OpenAI** | [platform.openai.com](https://platform.openai.com/api-keys) | Pick a model with "Test connection". |
| **Google Gemini** | [aistudio.google.com](https://aistudio.google.com/apikey) | Free tier available, with limits. |
| **OpenAI-compatible** | Ollama, LM Studio, OpenRouter, Groq, Together, DeepSeek, Mistral | Local models are free but usually weaker at Cantonese, so expect more replies to fail the checks. |

**Set a monthly spending limit** in your provider's console before you start. A short lesson of 10–20 messages typically costs a few cents on a mid-range model. The optional second opinion roughly doubles that.

## 2. Connect it

1. On the [learning site](https://jyltsang.github.io/Cantonlink-community/), open **AI tutor**, then **Add an API key**, or go straight to `#/ai`.
2. Choose the provider and paste the key.
3. Select **Test connection**. It lists the models your account can use; pick one, or keep the default.
4. Select **Open the AI tutor**.

### Free, private and local: Ollama

1. Install [Ollama](https://ollama.com) and pull a model, e.g. `ollama pull qwen2.5`. Models trained on a lot of Chinese tend to do better.
2. Allow the site to talk to it. Start Ollama with:
   ```sh
   OLLAMA_ORIGINS="https://jyltsang.github.io" ollama serve
   ```
   Use `http://localhost:8080` instead if you run the site locally with `npm run preview`.
3. In AI settings choose **OpenAI-compatible**, keep the address `http://localhost:11434/v1`, and type the model name (`qwen2.5`).

## Your key and your privacy

- **The key goes only to the provider you chose**, directly from your browser. The site is static: it has no server, collects nothing, and never sees your key.
- **By default the key lives in memory only** and is gone when you reload or close the page. Tick **Remember the key on this device** to keep it in this browser's storage. Don't do that on a shared computer. **Forget key** removes it.
- The site's Content-Security-Policy only allows connections to the listed providers and to `localhost`, so the page cannot send your key anywhere else.
- What you type in the tutor goes to your provider under their terms. The site does not store conversations.

## How replies are checked

AI models are fluent in Mandarin and written Chinese, but often slip when writing spoken Cantonese: 他是 instead of 佢係, wrong tones, or invented Jyutping. So the tutor asks the model for a structured reply (each word with its characters and Jyutping), and **every reply passes these checks in your browser**, shown under the message:

| # | Check | What it does | If it fails |
|---|---|---|---|
| 1 | **Structure** | The reply must be in the expected format | The tutor is asked to answer again (once) |
| 2 | **Valid Jyutping** | Every syllable must be real Jyutping with a tone number | Errors are fed back for one retry |
| 3 | **Characters match syllables** | One syllable per Chinese character | Fed back for one retry |
| 4 | **Spoken, not written, Chinese** | Flags written forms such as 他, 是, 的, 不, 了, 在 | Fed back for one retry |
| 5 | **Agrees with the library** | Words in the library must use the library's Jyutping | Multi-character words are corrected to the library reading; single characters, which can have several readings, are noted |
| 6 | **Grammar references are real** | Grammar patterns the tutor cites must exist | Invented references are removed |
| 7 | **Romanisation generated locally** | Yale and Bopomofo are always generated by the site from the Jyutping, never taken from the AI | Not applicable |
| 8 | **Second opinion** (optional) | A separate request asks the model to review the reply for naturalness | Shown as advice only |

Each reply then gets a badge:

- **Verified:** passed every check.
- **Corrected:** something failed and was fixed, by the retry or by the library. The list says what changed.
- **Unverified:** still failing after one retry. The reply is greyed out and **cannot be saved** for review. Don't learn from it.

### What the checks cannot catch

Checks 2–7 are rules, not a native speaker. A reply can pass every check and still sound unnatural, use an unusual word, or carry a subtly wrong translation. That is why every reply is labelled "AI-generated", why library content stays visually separate, and why every reply has a **Report** link. The second opinion helps, but it is the same kind of model judging itself.

The tutor also has the same six **library tools** as the [MCP server](MCP_GUIDE.md): vocabulary search, grammar patterns, Jyutping conversion, the written-Chinese check and practice questions. It looks words up instead of relying on memory, and you can see each look-up as it happens.

## For developers

| File | Role |
|---|---|
| [`tools/ai-providers.mjs`](../tools/ai-providers.mjs) | One chat interface over Claude, OpenAI, Gemini and OpenAI-compatible servers, using plain `fetch` (no SDK: the site has no build step and no dependencies) |
| [`tools/ai-checks.mjs`](../tools/ai-checks.mjs) | The checking pipeline and the reply schemas |
| [`tools/ai-tutor.mjs`](../tools/ai-tutor.mjs) | Prompts, the tool loop, check-and-retry, second opinion |
| [`tools/tool-definitions.mjs`](../tools/tool-definitions.mjs) | The six library tools, shared with the MCP server |
| [`site/tutor.js`](../site/tutor.js), [`site/ai-settings.js`](../site/ai-settings.js) | The chat screen, settings and key handling |

All of it runs in the browser. The tests use recorded provider responses (`tools/ai.test.mjs`) and a scripted local provider for the browser tests (`tests/mock-ai.mjs`), so CI needs no keys.

**Testing with real providers.** [`tests/live-ai.mjs`](../tests/live-ai.mjs) drives the real tutor in a browser against each provider whose key is set: a connection test, a short conversation, a Sifu correction, a translation, an explanation and a unit role-play. It reports every reply's badge and checks, and fails if there are network or CORS errors, if fewer than 80% of replies are Verified or Corrected, or if an Unverified reply could be saved. Run it locally with `ANTHROPIC_API_KEY=… npm run test:live -- --local`, or from the **Live AI provider test** workflow on GitHub using repository secrets.

Provider notes:
- **Claude** is called with the `anthropic-dangerous-direct-browser-access` header, which Anthropic requires for calls made from a browser. It uses API version `2026-10-21`, structured JSON output, and server-side refusal fallbacks (`fallbacks: "default"`).
- **OpenAI** uses strict JSON-schema output.
- **Gemini** and compatible servers rely on the prompt plus check 1.
